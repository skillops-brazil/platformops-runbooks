# Padrão de Versionamento — Conventional Commits

Regra obrigatória para **todo commit** nos projetos que usam esta biblioteca. O agente `build/15-commit`
e qualquer geração de mensagem de commit devem seguir este documento à risca.

## Identidade do autor

Configure a identidade do Git (ela **não** vai no corpo da mensagem — é o autor/committer):

```sh
git config user.name  "{Nome Sobrenome}"
git config user.email "{email@exemplo.com}"
```

> Preencha com a sua identidade. Este padrão **não** adiciona `Co-authored-by` nem qualquer trailer.

## Formato

```
tipo: descrição            # ou  tipo(escopo): descrição
```

## Regras

- **Tipos permitidos (apenas estes):** `feat`, `fix`, `refactor`, `docs`, `test`, `chore`, `ci`, `build`.
- **Mensagem em português.**
- **Título com no máximo 72 caracteres.**
- **Sem emojis.**
- **Sem** `Generated by Claude`, `AI-generated`, `Co-authored-by` ou qualquer referência a IA.
- **Ao gerar uma mensagem, retornar apenas a mensagem final do commit** — sem comentários ao redor.
- **Escopo** (opcional): use `tipo(escopo): ...` quando esclarecer o alvo (ex.: `fix(api): ...`); mantenha ≤ 72.
- **Corpo** (opcional): uma linha em branco após o título; explica o *porquê*, em português, sem trailers.
- **Quebra de compatibilidade** (se houver): `tipo!: descrição` no título.
- **Commits atômicos:** uma unidade lógica por commit; não agrupe mudanças não relacionadas.

## Exemplos

```
feat: adiciona integração com TargetGroupBinding compartilhado
fix: corrige healthcheck do serviço api-opseng-core
refactor: simplifica configuração de roteamento do ALB
```
